## 一、必改 bug

### B1 · `_raw()` 的坏应答 JSON 会穿透 `fill_slot`
- **触发**：Ollama 返回 HTTP 200，但 body 不是合法 JSON（代理改写 / 连接被截断），或返回的是 JSON 数组而非对象。
- **原状**：`json.loads(raw)` 写在 `try` 之外；抛出的 `JSONDecodeError` 不是 `AdapterError`，
  而 `fill_slot` 只 catch `ContextOverflow` / `AdapterError` → 异常直接冒泡出框架、best-of-N 中断，
  且**无法归类**（违反 R12「不留模糊失败」）。
- **改法**：把解码收进 `transport.chat()`，统一翻译成 `AdapterError`（可重试）；并校验应答是 `dict`。

### B2 · 返回的工具名只查 registry、不查是否属本节点授权集
- **触发**：模型幻觉/越权，返回一个「在 registry 里、但不在本节点工具集里」的调用（如 edit 节点返回 `write_file`）。
- **原状**：解析段只有 `registry.get(name)`，不比对 `tools_for()` 的结果 → 越权调用被当合法执行。
  R1「绝不暴露全集」只在**请求侧**不暴露，**网关侧**没真正强制。
- **改法**：`fill_slot` 先由 `tools` 算出 `allowed` 集合；`name ∉ allowed` 一律拒收（记为 `schema_violation`）。纵深防御。

### B3 · `record()` 落盘非原子，并发/中断会写坏画像文件
- **触发**：进程内两线程同时 `record`；或写盘中途进程被杀/断电；或另一实例正读到写了一半的文件。
- **原状**：`open(path, "w")` 直接截断再序列化；`_lock` 只护进程内，且 `pass_rate` / `tools_for` / `_load_profile`
  读 `profile` 都**不加锁**；坏文件被静默吞掉。
- **改法**：临时文件 + `fsync` + `os.replace` **原子替换**；读操作也加锁；`_load_profile` 遇坏文件先备份
  （`*.corrupt-<ts>`）再重建，绝不静默覆盖。
- **边界说明**：跨**进程**写同一文件仍是「后写覆盖前写」——已在 docstring 注明，
  建议每进程用独立 `profile_path`，事后再合并。

### B4 · `_load_profile` 对「能解析但结构不对」的文件不设防
- **触发**：`node_profiles.json` 是合法 JSON 但不是对象、或没有 `nodes` / `nodes` 不是对象。
- **原状**：直接 `self.profile["nodes"]` → `KeyError` / 后续 `.get` 崩溃。
- **改法**：形状校验，不合规按损坏处理（备份 + 重建）。

### B5 · `probes/export_rules.py` 导入路径与输出路径都错（附带修复）
- **触发**：直接 `python probes/export_rules.py`。
- **原状**：`sys.path` 插的是 probes 目录 → `import mythos_adapter` 直接 `ImportError`；
  且 `STAGE` 多拼了一层 `local-model-framework`，会把规则写进一个**不存在的嵌套目录**。
- **改法**：`sys.path` 插 `compatibility`；`OUTD` 指向真实 `compatibility`。
  **已验证**重生成的 `tool_rules.json` / `node_profiles.json` 与现网文件逐字节一致（无副作用）。

## 二、加固

### H1 · 传输层失败在 best-of-N 里立即放弃 → 改为有限重试
- **触发**：n=3 时第一次就网络抖动 / 连接被拒 / 读超时。
- **原状**：一次 `AdapterError` 直接 `return transport_error`，best-of-N 的预算全废。
- **改法**：纯网络错误最多重试 `transport_retries`（默认 2）次，指数退避（0.5s→1s→2s…封顶 8s），
  **不占**模型采样次数；上下文超限（确定性）与危险参数（R2 判死）**不重试**，保持原样。

### H2 · 温度阶梯只在「模型级失败」时前进
- **触发**：网络重试与时序被耦合到同一个 `temp` 游标上。
- **改法**：用独立游标 `fail_idx`，只有 `schema_violation` 才升温 0→0.7→1.0（R4 语义更纯）；
  网络重试沿用当前温度。

### H3 · `num_ctx` 未夹取上限
- **触发**：框架误传一个很大的 `num_ctx`。
- **原状**：直接透传，可能 OOM / 超时（E16）。
- **改法**：`_resolve_ctx` 夹到 `[1, CTX_MAX]`；节点无策略时兜底 `CTX_DEFAULT`。

### H4 · 归一失败会「静默放行错误类型」
- **触发**：模型把 integer 参数吐成 `"abc"`、把 boolean 吐成 `"maybe"`。
- **原状**：`_coerce` 返回原值，必填检查只挡空串 → **垃圾类型流进工具**。
- **改法**：归一失败抛 `SchemaViolation`（归入 R12 既有类别，**不新增 kind**）。同时：
  `object` 改**真正递归**（原来只递归一层）；`array` 支持 `items` 子 schema 且能解析 `'["a","b"]'`；
  `string` 收到 dict/list 时用 `json.dumps` 而非 Python `repr`。
- **说明**：这是本次唯一会改变**边界输入**行为的一处，方向是更严；正常输入与原实现完全一致
  （已用 41 例回归 + selftest 3/3 验证）。

### H5 · `check_safety` 每次调用重新 `re.search` 字符串
- **改法**：正则预编译（`rules._COMPILED`）；行为不变。

### H6 · `ask()` 会抛裸异常
- **触发**：问答时网络错误 / 超限。
- **改法**：也返回 `FillResult`（`transport_error` / `context_overflow`），与 `fill_slot` 一致（R12）。

## 一、必改

### B6 · 传输层把 localhost 请求交给了系统代理
- **触发**：`urllib.request.urlopen` 用默认 opener，会读系统代理（本机 = `http://127.0.0.1:7897`），
  于是发往 `127.0.0.1:11434` 的**本地**请求也被交给代理。
- **风险**：请求路径依赖代理进程；若代理被改为远端，源码/上下文会离开本机。破坏「出网必须关死、本地闭环」，
  也让「无外连」无法成立。
- **隔离证据**：`verification/isolate_proxy.py`（复跑）——把 HTTP(S)_PROXY/ALL_PROXY 指向死端口 `127.0.0.1:1`：
  默认 opener **失败**（URLError），显式 `ProxyHandler({})` **成功**。本机对照：默认 `urlopen` FAIL，
  `_NO_PROXY_OPENER` OK。
- **改法**：`transport.py` 构造**模块级** opener `_NO_PROXY_OPENER = build_opener(ProxyHandler({}))`，
  `chat()` / `list_models()` 全部复用它，不再每次新建。**未改动系统代理设置**（按要求）。
- **实测口径修正**：先前以为的 27 倍延迟是冷启动混淆；同一次热态下为 0.377s vs 0.239s（+0.14s/次）。
  故本条判据是「正确性与安全」，不是「提速」。
- **测试锁死**：`ProxyDisabledTest` 四例（无启用态 ProxyHandler / 对照默认 opener 带系统代理 /
  死代理下本地请求仍直达 / `chat()` 走模块级 opener）。
- **平台差异**：CPython 3.13 下 `build_opener(ProxyHandler({}))` 会把空的 ProxyHandler 优化掉
  （`.handlers` 里干脆没有 ProxyHandler）——同样是「无代理」；断言写成「不含**启用态** ProxyHandler」以兼容新老行为。

## 二、加固

### A1 · R5 边界：显式超交互上限 → stderr 告警（不硬禁）
- 决定：**不硬性禁止** > `CTX_INTERACTIVE_MAX`，也不新增「交互/批处理」开关；
  在 H3 夹取之外，显式传入 > `CTX_INTERACTIVE_MAX` 时向 stderr 打 warning（含**节点名**与数值），
  随后仍夹到 `[1, CTX_MAX]`。便于发现误用。
- 测试：`CtxWarningTest`（超限告警且不硬禁 / 策略默认值不告警）。

### A2 · `transport_retries` 可配置 + 按节点覆盖
- 决定：**保持默认 2**，但构造参数 `transport_retries` 支持两种形态：
  `int`（全局默认，向后兼容，旧的 `ad.transport_retries = 2` 仍生效）或
  `{"recon": 1, "edit": 3, "*": 2}`（按节点**类型**覆盖，`"*"` 为兜底）。
- 退避：**保持指数但不放大**（默认 2 次即 0.5s→1s 量级），不为等模型加载而加重试。
- docstring 写明：本机实测连接被拒约 **2s/次**，默认 2 次（含退避）**最坏总代价约 6–8s**；
  交互敏感节点应下调。
- 实测依据（主控提供，脚本 `verification/measure_retry_budget.py` / `verification/verify_retry.py`）：
  连接被拒 2.05s/次（裸 socket 层同值），3 次尝试含退避共 7.61s；
  模型冷启动 14.72s / 热态 0.15s——**加载是「慢」不是「错」**。
- 测试：`transport_retries` 覆盖 / int 兼容 ×2。

### A3 · R12 新增失败类别 `unauthorized_tool`（越权单列）★本轮新增类别
- 决定：**同意单列**。安全相关事件必须能与「格式噪声」分开计数与告警。
- 改法：`fill_slot` 里区分两种拒收——
  · `name` 在 registry 里、但不在本节点授权集 → **`unauthorized_tool`**（安全事件，立即判死、`calls=[]`）
  · `name` 连 registry 都没有 → 视为格式噪声，仍归 `schema_violation`（依据 E9）
- 同步更新：`mythos_core/types.py::KINDS`（唯一真相源）、`mythos_adapter.KINDS` 重导出、
  `tool_rules.json::R12`、`probes/export_rules.py`（R12 语句改为由 `MA.KINDS` 生成，防漂移）、readme。
- 测试：`FillSlotLogicTest.test_unauthorized_tool_rejected`（kind / 立即判死 / `calls` 为空）。
