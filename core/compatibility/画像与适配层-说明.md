# 多模型画像与适配层 · 说明（v0.2）

本文件回答一个问题：**换一个本地模型，要改什么、不改什么。**

上一轮（Mythos V2-8B）把兼容层拆成了「模型专属」与「通用」两层。本轮把这份拆分
落成一个正式的**画像（profile）**结构，并接入第二个模型（Qwen2.5-Coder-7B）作为验证：
如果换模型真的只需要换画像，那这次接入应该只写数据、不碰逻辑。

结论：成立。新模型的接入是**一份数据 + 一个门面类**，安全口径（R1/R2/R9/R12）、
传输层（禁系统代理）、参数归一、失败归类**一行都没改**。

---

## 1. 画像是什么

`compatibility/mythos_core/profiles.py` 里的 `ModelProfile` —— 一个模型一份，字段如下：

| 字段 | 含义 | 换模型要重测吗 |
|---|---|---|
| `model` | Ollama 模型名 | 是 |
| `toolsets` | 每个节点授权哪些工具（R1） | 是（但默认沿用同一套，除非实测有理由放宽） |
| `think_policy` | 每个节点开不开思考（R3） | 是 |
| `sends_think` | 能不能把 `think` 键发出去 | **是（有模型收到直接 400）** |
| `ctx_policy` / `ctx_max` / `ctx_interactive_max` | 上下文配额（R5） | 是 |
| `temp_ladder` | 采样温度阶梯（R4） | 否（默认沿用） |
| `extract_from_content` | 是否要从正文里抠工具调用 | **是（有的模型不走原生通道）** |
| `recon_max_turns` / `edit_max_turns` | 节点轮次预算 | 是（不同模型「耐心」差很多） |
| `edit_prompt_hint` | 挂在编辑节点系统提示后的一段话 | 是 |
| `notes` / `evidence` | 结论与**实测依据** | —— |

画像里每个字段后面都跟着实测编号（S1…S8、E1…E16）。没有实测支撑的数字不写；
这条纪律是上一轮运维期定下的，本轮继续执行。

## 2. 两份现役画像

### 2.1 Mythos V2-8B（q4_k_m）—— 原生通道派

- 原生 `tool_calls` 通道可用，正文里不出现工具调用；
- 支持 thinking；但**编辑节点必须开思考**，关掉它会从最小补丁退化成整文件重写（E15）；
- `format` 与 `tools` 互斥（E6），这条对所有模型都成立，见下；
- 依据：四轮探针 40 用例（`probes/probe.py` ~ `probe4.py`）。

### 2.2 Qwen2.5-Coder-7B —— 正文 JSON 派（本轮新接）

体检（`probes/model_smoke.py`）先发现三件事，直接决定了它的画像：

| 发现 | 证据 | 画像里的应对 |
|---|---|---|
| **不走原生 `tool_calls` 通道**：请求体带 `tools`，它仍把调用写成正文里的一段裸 JSON | S1 | `extract_from_content=True` |
| **不支持 thinking**：带 `think` 键直接 `HTTP 400 does not support thinking` | S3 | `sends_think=False`（传输层直接把键摘掉） |
| 上下文 32768（Mythos 40960），其它脾气相近 | S2 `format+tools` 同样丢工具通道 | `ctx_max=32768` |

接着的 12 条探针（`probes/probe_qwen_coder.py`）给出 **11/12**，唯一的失败是 `format` 与
`tools` 共存——与 Mythos 完全一致，**这是跨模型确认的一条边界**，不是某个模型的怪癖。

然后状态机真机跑（三轮）又暴露三个只有跑起来才会看到的问题：

| 发现 | 证据 | 画像里的应对 |
|---|---|---|
| 正文 JSON 里写文档字符串时**不转义引号**（`"""…"""` 原样敲进去） | S7（wo-qwencoder-01） | 通用层加 JSON 修复档（见第 4 节） |
| **不会算行号**（无 thinking）：把补丁插进了错误的函数，还留下不可达代码 | S8（wo-qwencoder-03） | `edit_prompt_hint` 要求改用「按原文替换」；类型 gate 的死代码检查兜底 |
| 拿到 gate 反馈后**重复提交同一份错补丁**；读节点会连烧 3 轮却给不出结论 | S8 | `edit_max_turns=2`、`recon_max_turns=1`、引擎加重复补丁熔断 |

改完画像后第二轮真机跑：**3.3 秒通过**，一行文本锚点替换，三个 gate 全过。
同一道题 Mythos 是 14–150 秒、qwen3.5:9b 是 56 秒。它是四个模型里最快的一个。

## 3. 谁专属、谁通用（本轮确认过的边界）

```
compatibility/
├── mythos_core/
│   ├── profiles.py   【模型专属数据】两份画像 + 每个字段的实测依据   ← 换模型只改这里
│   ├── config.py     【Mythos 默认值】保留，作为画像的默认来源
│   ├── rules.py      【规则】R1 工具集 / R2 危险参数
│   ├── extract.py    【通用】从正文里抠工具调用 + 手写 JSON 修复      ← 本轮新增
│   ├── params.py     【通用】参数归一（R9）
│   ├── transport.py  【通用】出网 + 解码 + 禁系统代理（B6）
│   ├── types.py      【通用】FillResult + 失败分类全集（R12）
│   └── errors.py     【通用】异常类型
├── mythos_adapter.py      门面（画像驱动；不传 spec 时行为与之前完全一致）
└── qwen_coder_adapter.py  新门面：同一个内核，换 QWEN_CODER 画像（约 100 行）
```

`qwen_coder_adapter.py` 的全部逻辑就是「继承 + 换画像 + 打印画像差异」。
这不是「复制一份改改」，而是同一个门面换一份数据 —— 规则只有一处真相源，
换模型不会让安全口径悄悄分叉。

## 4. 通用层新增：正文抠调用 `extract.py`

模型把调用写在正文里时，框架拿到的是「一段看起来像 JSON 的文本」——没有这一层，
这个模型等于没有工具通道（第一轮真机跑就卡在这里）。它做四件事：

1. **取候选**：先扫 ```json 围栏，再按花括号配平（不是非贪婪正则——正则会在嵌套处截断）；
2. **修格式**：依次尝试原样 → 去尾逗号 → 修未转义引号/裸换行 → Python 字面量（单引号 dict）；
3. **归一形状**：`name` / `tool` / `function.name`，`arguments` / `parameters` / `args`，
   且 `arguments` 可以是 dict 也可以是 JSON 字符串；
4. **不越界**：只在**工具表白名单**内认；白名单内没抽到、但正文里确实有调用形状的对象时，
   按 R12 归为格式噪声（`schema_violation`），而不是默默当成「模型在聊天」——
   否则越权与幻觉会被降级成「空调用」，安全事件就丢了。

最后一条的取舍值得说明：宁可多报一次格式噪声（换温度重试一次的成本），
也不要把一次越权悄悄吞掉。安全事件必须可计数、可告警。

修复层**只修格式，不替模型编内容**：模型自己写坏了引号（少一个），解析结果与原文保持一致，
不会自动补一个让它「看起来对」。

## 5. 换新模型的操作清单

1. 体检：`python probes/model_smoke.py <模型名>`（5 个用例，看四件事：
   有没有原生通道、`format` 会不会顶掉工具、`think` 收不收、补丁写不写得对）；
2. 画像：在 `profiles.py` 加一份 `ModelProfile`，字段按体检结论填，`evidence` 写实测编号；
3. 门面：如果要单独的适配入口，加一个 `XxxAdapter(MythosAdapter)`（约 100 行，只换画像）；
4. 探针：拷 `probes/probe_qwen_coder.py` 改成新模型的用例集，跑出 `probe_xxx_results.json`；
5. 真机：`python statemachine/cli.py run --adapter <key> ...` 跑一道真实工单；
6. 回归：`compatibility/test_mythos_adapter.py`、`test_qwen_coder_adapter.py`、
   `statemachine/test_statemachine.py`、`verification/verify_sm_rules.py` 四套全绿；
7. 把真机跑出来的新毛病补进画像（轮次预算、提示增补），并在本文档记一行。

第 6 步不可省：安全口径的回归测试是「换模型不换边界」的唯一证明。
