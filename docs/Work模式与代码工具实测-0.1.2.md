# Anvil IDE 0.1.2 本机实测

2026-11-25，Windows x64，RTX 4070 Laptop 8 GiB，Ollama 0.40.18。每个模型使用同一组临时文件和合成源码，两组各跑一轮。

| Ollama 标签 | Work（5 题） | 代码（10 题） | Work 非首题中位耗时 |
|---|---:|---:|---:|
| `fableforge-ai/mythos-v2-8b:q4_k_m` | 5/5 | 10/10 | 0.50 秒 |
| `glm4:9b` | 5/5 | 9/10 | 0.76 秒 |
| `llama3.1:8b` | 5/5 | 9/10 | 0.47 秒 |
| `qwen3:8b` | 5/5 | 10/10 | 0.58 秒 |
| `anvil-qwen3.5:9b` | 5/5 | 10/10 | 1.21 秒 |
| `qwen2.5-coder:7b` | 5/5 | 10/10 | 0.53 秒 |
| `fableforge-ai/mythos-v2-8b:latest` | 5/5 | 10/10 | 2.60 秒 |

Work 的只读题核对全部文件名。四道移动题逐项核对清单、目标路径和文件内容，然后新建历史管理器，撤销并核对根目录。耗时包含规划、执行及撤销，表中的中位数排除了该模型首题，不能代表冷启动。代码编辑按整份预期文本比对，只读题检查答案及有无写入提议。

## 模型与协议

- GLM-4 使用约束 JSON、工具示例和嵌套补丁解包；请求中省略 `think`。AutoClaw 的 2026-09-30 本机记录曾复现思考参数报错、工具示例缺失及嵌套参数被丢弃。
- Qwen3.5 的本机 GGUF（Q4_K_M）以 `anvil-qwen3.5:9b` 注册。Work 优先走 Ollama 原生工具，失败时可切换约束 JSON；前期四题用纯 JSON 时通过两题，启用原生工具后同四题全部通过。
- Qwen2.5-Coder 可接收完整的 `<tool_call>`、`<tools>` 或独立 JSON 调用。解析器有单独的 XML 回归测试。原生、XML 和 JSON 都要经过同一动作与参数校验。
- Mythos 的 Work 请求关闭思考以降低延迟。代码场景保留模型默认思考设置。Qwen3 控制思考开关，Llama 3.1 与 GLM 在短文件的只读问题上优先直接作答。

## 未达标样例

- `glm4:9b` 找到了长文件第 107 行，将 `return 173` 改为 `return 173 + 2`。结果等于 175，但此次按预期补丁 `return 175` 逐字评分，所以计为未通过。
- `llama3.1:8b` 在输入值等于阈值时选错了严格小于分支，回答 `HARBOR-52`，实际应为 `PEBBLE-26`。

## 安装包验证

Windows x64 安装包版本为 0.1.2，SHA-256 为 `C2D884059836B8DC3F4CD21B1E676641E9A1F0F57C22358D69745FCBC5E8B8E5`。从安装包提取的应用归档与接受界面测试的归档哈希相同。GLM-4 和 Qwen3.5 在打包后的聊天窗口完成了授权目录、预览、确认移动、解除并重新授权、撤销及逐字核对文件内容。另有 33 项自动回归全部通过，包含 Windows 短路径、链接、重名和操作中断恢复。

## 复测

在项目目录执行以下命令。所有参数均为本地 Ollama 已安装的模型标签。

```powershell
npm run bench:work -- glm4:9b qwen3:8b anvil-qwen3.5:9b
npm run bench:chat -- glm4:9b llama3.1:8b
```

两套脚本都输出逐题 JSON。样例也用于适配开发，结果适合检查版本回归。
