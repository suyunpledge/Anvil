## F2. 安全加固（2026-09-28 外部审查后）

审查提了 7 条，逐条核实属实并已全部修复（详细对照表见 `CODEX-HANDOFF.md` 第 4.1 节）：

| # | 问题 | 修复要点 |
|---|---|---|
| 1 | 测试子进程继承全部环境变量（可读密钥 / 走代理外发） | `sandbox.py`：干净环境 + 代理置空 + HOME 隔离；**明确声明这是缓解不是沙箱** |
| 2 | 服务可被绕过人工确认（CORS `*` + 无鉴权 + 客户端决定确认） | 令牌 + CORS 收窄到 localhost/vscode-webview + **服务端强制确认** + 可选目录白名单 |
| 3 | 运行期间改文件会被静默覆盖 | 版本基线提到**工单开始前**记；`_stage` 与 `confirm` 两处比对 |
| 4 | 流式接口绕过出网熔断；异常时审计写死 200 | 抽出 `post_ollama_stream()` 共用同一道门；审计如实记状态 |
| 5 | tidy 确认界面看不到移动方案（无效赋值） | 服务下发完整清单，扩展收下并渲染 |
| 6 | 上下文层未接入实际链路 | 新增 `context_provider` 注入点，服务侧接上（优先读暂存区） |
| 7 | 工作目录=项目根时可能递归复制 | 检测嵌套→暂存区移到系统临时目录；忽略表补 `.runtime` |

**修复中另发现一个自家缺陷**：上下文层接入后同题变差——裁剪后 221 token，整文件才 106 token。
小文件上"裁剪"反而让模型看不清文件布局。现在的口径是**只有真省才用**
（不小于全文 90% 就回退全文），回归测试 `test_long_context_falls_back_to_full_text`。
教训：优化项要在**它不该生效的场景**也测一遍。
