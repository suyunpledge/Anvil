### 第四轮（10-01 00:00）—— glm4:9b 平反（用户情报触发）

用户指出：**GLM-4-9B 原生支持工具调用，是 ollama 模板没打包好**。实测验证属实，
挖出三层根因（全修）：

1. **think 400**：glm4 不认 `think` 键 → 补 GLM4 画像（`sends_think=False`），
   网关按 `PROFILE_BY_MODEL` 摘键。
2. **零样本不发起调用**：ChatGLM 模板只做输入侧工具注入，模型把"无法访问"写成正文；
   加 few-shot 格式示范（`edit_prompt_hint`）后能稳定输出 ChatGLM 官方裸 JSON。
   `extract_tool_calls_from_content` 对裸 JSON 与 ```json 围栏都能提取（本就能抠）。
3. **嵌套 patch 掉进 `**extra`**：glm4 输出 `patch:{old_string,new_string}` 嵌套对象，
   `apply_patch` 旧签名只认扁平参数 → `PatchError: 补丁参数不足` → 补丁静默失败两轮
   → escalated。已在 `tools.py::apply_patch` 入口统一解包（**全部模型受益**）。

顺手修了第四个 bug：micro_bench 建单时 adapter 写死 `"mythos"`——现在按模型名路由画像
（`pick_adapter`）。这也解释了第二轮 gemma4/ministral/qwen3.5 为什么能用：它们行为
恰好与 mythos 画像兼容，属于"蒙对"。

**结果：glm4:9b PASS 5.4s o/o/o（两次复测稳定）——全库最快。**

## 核心教训

1. **「模型不行」要区分「模型能力」与「适配层没接对」**——9/28 体检判 glm4
   "不会调工具"，实为三层适配问题叠加。下次遇到"模型不调工具"先查：
   think 键兼容 → 提示格式示范 → 工具参数结构（扁平 vs 嵌套）。
2. Ollama 模板层的 `does not support tools` 是硬限制（模型声明有 tools 但模板没实现），
   改框架代码绕不过。
3. 秒失败（<1s）≠ 模型能力问题，通常是路由/模板/参数层的 400。
4. 慢失败（>300s）在 8GB 显存机器上优先怀疑显存溢出（`ollama ps` 看 CPU/GPU 百分比）。
