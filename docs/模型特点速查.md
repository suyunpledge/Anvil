## 三、适配层要记住的四条

1. **`sends_think=False` 不是可选项**：模型不收 `think` 键时会直接 HTTP 400，
   网关按 `PROFILE_BY_MODEL` 摘键——没登记画像的模型会在这里翻车（glm4、llama3.1 都栽过）。
2. **正文通道（`extract_from_content=True`）是第二梯队模型的救星**：把工具调用写成
   正文 JSON 的模型，靠 `mythos_core.extract` 抠出来就能正常工作（qwen-coder、glm4、deepseek-r1）。
   修复层容错顺序：原样 → 去尾逗号 → 修引号/裸换行 → **补缺失右括号** → Python 字面量。
3. **提示要给格式示范**：正文通道的模型几乎都需要 few-shot 例子才会输出正确格式
   （`edit_prompt_hint` 里带一个完整调用示例）。只写"请调用工具"没用。
4. **参数结构要兼容**：模型可能给扁平参数，也可能给 `patch:{...}` 嵌套——工具层统一解包
   （`apply_patch` 已做）。

## 四、选型建议

| 场景 | 首选 | 理由 |
|---|---|---|
| 交互式改代码（人盯着） | `qwen2.5-coder:7b` / `glm4:9b` | 3-6s，几乎瞬时 |
| 稳定批量改代码 | `gemma4:e4b` / `ministral-3:8b` | 原生通道，行为可预期 |
| 需要复杂推理 | `qwen3:8b`（慢）/ `mythos-v2-8b:latest`（更慢） | 带 thinking，质量优先 |
| 文件整理（tidy 链） | `glm4:9b` / `qwen2.5-coder:7b` | 判断简单、执行机械，快就完事 |
| 显存受限（8GB 卡） | 只考虑 4-9B q4 | 14B+ 必落 CPU，不可交互 |

## 五、一句话总结

**「模型不行」和「适配层没接对」是两件事。** 四个曾被判死刑的模型（glm4 / qwen-coder /
deepseek-r1 / deepseek-coder）复审后，前三个都成了主力；真正的硬限制只有三条：
显存装不下、Ollama 模板没实现工具通道、模型本身不调工具。
