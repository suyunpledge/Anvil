## 一、确凿问题（已修复 + 回归）

### A.（中）`/staged` 接口无鉴权，且返回完整本地路径与文件内容

- **位置**：`service/app.py::staged`、`extension/extension.js::reviewDiff`
- **问题**：写接口都加了令牌，但这个**敏感读口**漏了——它返回暂存文件全文和 `real_path`
  （本机绝对路径）。本机任意进程可匿名读取。上次加固时"读接口不鉴权便于自检"的口径
  对 `/health`、`/presets` 成立，对 `/staged` 不成立——它泄露的是用户代码内容。
- **修复**：① `/staged` 要求令牌；② 响应不再含 `path`，只回 `filename`；
  ③ 扩展改用 `findFiles` 在工作区按名定位，拿不到就明确提示而不是瞎猜路径。
- **回归**：`service/tests/test_review_fixes.py::StagedAuthTest`（401 + 响应不含绝对路径）
- **顺带**：扩展 `reviewDiff` 原来用 `request`（无令牌）——修 `/staged` 鉴权后它本来就会 401，
  这次一起改成 `authed`。

### B.（高，外部审查 #3 的遗留）免确认路径缺落盘终检

- **位置**：`core/statemachine/engine.py::_commit`
- **问题**：上次修复覆盖了"人确认"路径（runner 里双重版本比对），但 **`autoApply` 免确认
  路径**从 `_stage` 到落盘之间没有再比对——模型运行期间文件被旁路改过的话，
  这条路径仍会静默覆盖。这是我自己上次修复不彻底。
- **修复**：`_commit` 在替换前比对 `initial_version`，不符抛 `Terminal(STATUS_FAILED)`，
  与人确认路径同口径（文件一个字节不动，提示重新建单）。
- **回归**：`test_review_fixes.py::AutoApplyVersionCheckTest`（两条：被改→拒绝且人工改动保留；
  未改→正常落盘）。为可测试性给引擎加了 `_test_hook_before_commit` 钩子（仅测试回调，不改行为）。

## 三、疑点核实为误报（写下来防止下次重复怀疑）

| 疑点 | 核实结果 |
|---|---|
| e2e 脚本里 `TOKEN = "***" + ...` 像是占位符没写完 | **误报**：那是 exec 输出对 `e2e-token-<时间戳>` 的脱敏显示（TOOLS.md 记过该特性）；源码正常，16/16 由它跑出 |
| `sm_ref` 在 `sm.run()` 之后才赋值，闭包拿不到 staging | **误报**：字符位置核过，赋值在 run 之前；且首轮 provider 调用时 staging 尚未建立，`builder` 会回退真实目录，行为正确 |
| `sandbox` 可能把 `LOCAL_IDE_TOKEN` 泄给被测代码 | **误报**：实测 `LOCAL_IDE_TOKEN not in sanitized_env()` 为 True（`token` 前缀在丢弃表里） |
| 网关 `/ollama/api/chat` 绕过出网门 | **误报**：它走 `post_ollama()`，该函数第一行就是 `assert_url_allowed` |
| tidy 的 confirm 缺基线 | **误报（部分）**：`_tidy_scan` 在进入待确认时已缓存，confirm 用缓存重放；tidy 场景是"移动文件"而非"覆盖文件"，风险面不同，`verify_after` 有计数守恒兜底 |
